# 双源数据合同

## 两张表的职责

| 数据源 | 主要字段 | 唯一用途 | 禁止用途 |
|---|---|---|---|
| ID 层级数据 | `product_id`、`shop_id`、`shop_operation_country`、`product_new_cbec_industry_l3`、`payment_1d`、`dollar_cost`；广告字段可选 | 经营指标、排名、聚合、店铺与商品 ID 对齐的唯一事实源 | 不用名称表中的指标覆盖它 |
| 名称对照数据 | `product_id`、`product_name`、`shop_id`、`shop_name`；国家和类目可辅助校验 | 理解商品语义、店铺显示名和历史别名 | 不加总 GMV、消耗、曝光，不因重复名称复制指标 |

`product_id`、`shop_id` 一律按字符串读取。店铺改名仍以 `shop_id` 校准；商品多标题仍以 `product_id` 校准。

## 输入校验

1. 两表都必须有完整表头和至少一条有效记录。
2. ID 层级表至少包含：
   - `product_id`
   - `shop_id`
   - `shop_operation_country`
   - `product_new_cbec_industry_l3`
   - `payment_1d`
   - `dollar_cost`
3. 名称表至少包含：
   - `product_id`
   - `product_name`
   - `shop_operation_country`
   - `shop_id`
   - `shop_name`
4. 接受大小写、空格和常见下划线差异，但字段映射必须在方法说明中写明；不凭位置猜字段。
5. 数字字段允许千分位、空白和百分号。空值不得默认为零；应区分“0”和“缺失”。
6. 两表应属于同一商家、同一客户数据周期。无法从表内验证时，以用户明确确认作为证据并记录。
7. 国家、店铺和商品 ID 之间出现冲突时，保留冲突记录并暂停相关行的建议，不静默合并。
8. 金额口径/币种由用户明确确认并写入审计；输入无币种字段时不得凭字段名静默假设。

## 清洗与关联

1. 去除 ID 两端空格，不转换成浮点数。
2. 经营事实粒度固定为：

   `shop_operation_country × shop_id × product_id`

3. ID 层级表若在该粒度重复，分别加总 `payment_1d` 和 `dollar_cost`，再计算：

   `weighted_roas = sum(payment_1d) / sum(dollar_cost)`

   当总消耗为 0 时，ROAS 标为不可计算，不写成无穷大。
4. `ads_ctr`、`ads_cvr`、`ads_cpm` 等比率没有原始分子分母时不得做简单平均；只可保留同一事实粒度的原值或标为方向性参考。
5. 名称表优先按 `shop_id + product_id` 关联；只在该组合缺失时以 `product_id` 做语义补充，并标记为跨店回填。
6. 同一 ID 有多个名称时，保留全部别名；展示时选择信息最完整的非空名称，并注明“存在历史/重复名称”。不要用名称判断为多个商品。
7. 同一 `country + shop_id` 只生成一个标准展示名，商品行和店铺汇总统一复用；附其他别名。没有名称时间戳时不得称其为“当前/最新店名”。任何计算仍以店铺 ID 为准。
8. 名称表里的 GMV、消耗、ROAS、曝光等字段即使存在也不参与计算。
9. GMV、消耗等指标先保留源精度完成聚合与比率重算；只在最终展示层四舍五入，避免逐行取整后再加总。

## 口径边界

- `payment_1d` 在报告中展示为源字段对应的 GMV；若用户另有正式定义，以其定义为准并改写字段说明。
- 只分析本次提供的数据覆盖范围。若是 Top 商品截面，不把加总值称为“客户整体大盘”或“全店占比”。
- 核心货盘 GMV、迁入 GMV、店外占比等均是“所选候选商品范围内”的数，不外推到完整商家。
- 保留用户确认的币种/口径；不同国家或币种的数据不得直接合并成一个金额总计或跨国排名。
