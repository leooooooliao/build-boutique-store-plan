# 双源数据合同

## 最高优先级原则

内部报表是本任务不可改写的事实源：**报表输出什么，就按什么分析。**

- 不纠正、平滑、补造或用外部数据覆盖内部报表数值。
- 不因数值看起来异常而要求用户解释或重拉。
- 只检查文件传输是否破坏了结构或长 ID；这不等于质疑源数据。
- 营销参谋只用于发现补品和提供外部类目证据，不反向修改客户货盘事实。

## 两张表的职责

| 数据源 | 核心字段 | 用途 | 禁止用途 |
|---|---|---|---|
| ID 层级数据 | `product_id`、`shop_id`、`payment_1d`；国家、L3、cost 和广告字段按实际输出读取 | 经营指标、排名、聚合以及商品和店铺 ID 对齐的唯一事实源 | 不用名称表或营销参谋覆盖其数值 |
| 名称对照数据 | `product_id`、`shop_id`；`product_name`、`shop_name` 按实际输出读取 | 理解商品语义、具体店铺显示名和历史别名 | 不加总经营指标，不因重名复制数值 |

`product_id`、`shop_id` 始终按字符串读取。商品或店铺改名仍以 ID 校准。

## 实体定义

- `merchant_name`：客户、集团或商家主体名称，只用于标题和任务标识。
- `shop_id`：经营计算与承接店选择的店铺实体。
- `shop_name`：具体店铺的显示名称或历史别名。

集团名与 `shop_name` 不同是正常层级关系，不作为商家不匹配，也不向用户追问。一个 Shop ID 出现多个店名时保留别名；没有时间戳时不宣称哪个是“最新名称”。

`merchant_name` 缺失不影响经营分析；使用“目标客户”作为临时展示标签继续，正式交付前可再补标题。

## 输入检查

只把以下问题判为阻断：

1. 文件无法读取、为空或没有可识别表头。
2. 两张来源表缺失，或无法按表头区分。
3. 隔离少量明显传输损坏行后，`product_id` / `shop_id` 仍整体不可用。
4. ID 层级表完全没有可用商品—店铺记录。

损坏行不使用模糊比例阈值：脚本逐行隔离明显传输损坏，只在隔离后完全没有可用经营行或名称表 Product ID 整体不可用时阻断。

其他问题均继续处理：

- L3 为空或整列缺失；
- `dollar_cost`、广告字段及其他可选指标为空或非数字；
- `product_name`、`shop_name` 或国家为空；
- 同一 Product ID / Shop ID 对应多个名称；
- 数据只覆盖部分国家；
- 集团名与店铺名不同；
- 数值为 0、极端值或看起来不符合经验。

## 自动处理

1. **L3 缺失：** 根据商品名、别名和其他可用类目字段判断商品原型；保留 `source_l3` 与 `inferred_l3`，明确这是 AI 判断，不覆盖原始值。没有足够语义时使用“类目待识别”，该行仍可参与数值汇总。
2. **名称缺失：** 尝试同 Product ID / Shop ID 的其他别名；仍无名称时展示 ID 和可判断的商品原型，不阻断。
3. **国家缺失：** 若同一 Shop ID 在其他记录中只对应一个国家，可标注为推断；否则隔离该行的分国与主题分析并保留审计记录，不影响其他国家。不得把未知国家悄悄并入某个国家。
4. **可选数值缺失：** 该值不参与对应指标的加总或比率计算，其他有效字段继续使用。空值永远不等于 0。
5. **重复记录：** ID 主数据按事实粒度聚合；名称表只建立别名字典，不复制经营指标。

## 清洗、关联与计算

1. 去除 ID 两端空格，不把 ID 转为浮点数。
2. 经营事实粒度为：

   `识别到的国家 × shop_id × product_id`

3. 可加指标只加总有效数值，保留每个指标的有效行数或 GMV 覆盖率。
4. GMV 排名使用全部有效 `payment_1d`。
5. ROAS 只使用 GMV 与 cost 同时有效的记录重算：

   `matched_roas = sum(payment_1d_on_cost_valid_rows) / sum(valid_dollar_cost)`

   cost 全部缺失或分母为 0 时写“不可计算”，不得用全部 GMV 除以部分 cost。
6. CTR、CVR、CPM 等比率只有在原始分子分母齐全时才重算；否则保留原粒度方向性值或不展示，不能简单平均。
7. 名称优先按 `shop_id + product_id` 关联；该组合缺失时可用 `product_id` 做语义补充，并标注跨店回填。
8. 同一 ID 的多个名称全部保留，展示信息最完整的非空名称；不要把多个标题当成多个商品。
9. 只在展示层四舍五入。
10. 全量 `国家 × shop_id × product_id` 聚合留作审计；商品强度另按 `国家 × product_id` 跨 Shop 汇总，并保留每个来源 Shop 的明细，避免同一商品被拆弱或重复入选。
11. AI 默认只读按 `payment_1d` 排序的 Top 100 精简候选池；主题不足、名称覆盖不足或 GMV 分散时自动扩至 Top 200。该阈值只控制分析效率，不是输出配额，也不需要用户确认。

一个工作簿有多张疑似表时，随包脚本先按核心表头匹配度选择最高分工作表，同分按 Sheet 名稳定排序，并在校验回执中展示最终选中的 Sheet。等价实现应沿用同一原则；只有完全无法识别两类来源时才向用户追问。

## 国家与金额口径

- 国家从 ID 数据自动识别，不要求用户先确认完整市场清单。
- 缺少某个国家不是异常。最终说明“本次只分析输入中识别到的国家；未出现的国家未纳入，不代表商家必须经营或退出该市场”。
- 金额沿用内部报表源字段的既定口径，不要求用户改值、换算或修正。
- 不同国家分别展示；没有源数据明确支持时，不做跨国金额合计或排名。

## 使用边界

- 只分析本次文件覆盖范围；Top 商品截面不等于客户整体大盘。
- 核心货盘 GMV、迁入 GMV、店外占比等均只描述候选商品范围。
- 不用内部报表推导新店 GMV 承诺、市场份额或完整客户规模。
