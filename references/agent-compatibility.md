# 跨 AI 兼容

本 Skill 以输入、规则和输出合同为核心，不依赖某一个代理的专有工具名。

## 最低能力

代理至少需要：

- 读取两份制表符文本、CSV 或 XLSX；
- 把长 ID 当作字符串处理并进行分组聚合；
- 生成可编辑的中文文档；
- 明确区分可验证事实、估算和 AI 判断。

推荐确定性路径需要 Node.js 18+ 和可执行命令行，用于运行 `scripts/*.mjs`。若宿主没有 Node：

- 可用 Python、SQL 或电子表格工具严格复现 `data-contract.md` 和 `quality-gates.md`；
- 必须输出相同的行数、匹配率、命名 GMV 覆盖率、分国汇总和 QA 结果；
- 明确写“未运行随包 Node 脚本，使用等价实现复核”，不得声称脚本校验已通过。

访问营销参谋还需要使用者已有的内部账号、页面权限和一个可复用登录态的浏览器。创建飞书文档需要使用者已有的飞书写权限。

## 能力路由

1. **存在 `build-gcrm-hot-product-report`：** 优先调用，并按本 Skill 的主题和时间窗口传参。
2. **没有该 Skill、但有已登录浏览器：** 按 `gcrm-integration.md` 手动完成筛选、采集和核验。
3. **没有营销参谋登录态：** 执行降级；只完成客户货盘重组，不生成虚假补品数据。
4. **可写飞书：** 按 `output-contract.md` 创建并读回检查。
5. **不可写飞书：** 输出结构相同的 Markdown/HTML；不要声称已创建飞书文档。
6. **无法解析 XLSX：** 要求用户复制为保留表头的制表符文本或 CSV，不通过截图抄数。

## 工具无关原则

- 可以使用 Python、JavaScript、电子表格公式或代理原生数据工具，但清洗和聚合结果必须满足 `data-contract.md`。
- 自动化脚本负责确定性工作：字段校验、长 ID、去重、关联、加总和加权 ROAS。
- AI 负责语义工作：商品理解、主题组合、内容表达和风险判断；不得覆盖脚本算出的事实。
- 任何工具失败都应降级并披露，不得伪造“已抓取”“已上传图片”或“已写入飞书”。

## 权限与数据安全

- 公开仓库公开的是方法，不是内部系统访问权。“能看到链接”不等于“有权限访问”。
- 不提交客户原始数据、截图、商家名称、登录 Cookie、Token、带敏感查询参数的 URL 或生成报告到公共 Skill 仓库。
- 文档按使用者组织的数据分级策略保存和分享；跨组织发送前由使用者复核。
- 不要求使用者把账号密码交给 AI，不尝试绕过登录或权限控制。
