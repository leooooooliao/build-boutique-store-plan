# Aime、Mira 与其他 AI 的使用方式

本 Skill 以数据合同、浏览器证据和输出合同为核心；AI 可以更换工具，但不能省略营销参谋。

## 开始前的浏览器预检

- **Aime：** 提醒用户点击输入框下方【拓展】并开启【Aime Chrome】；“Aime Chrome”就是开关实际名称。操作当前已经登录的本地浏览器，不使用云端浏览器授权。`get_tabs` 只完成标签页发现，不能在这里停止；取得 GCRM tab 后继续运行 `dependencies/gcrm-core/build-filter-plan.mjs` 并按其 selector 操作。
- **Mira：** 使用其可操作本地已登录浏览器的能力；执行者应根据当时真实界面给出一个具体授权动作，不知道按钮名称时不要编造。
- **其他 AI：** 优先使用用户当前已登录的本地浏览器，并把通用提醒改写为该宿主能够确认的一步操作。不要把新开的云端浏览器、无登录沙箱或搜索引擎结果当作营销参谋。

浏览器能力与 Skill 安装是两件事。即使已安装 `build-gcrm-hot-product-report`，也要先验证浏览器登录态和页面可操作性。

## 最低能力

执行者至少需要：

- 读取含两张 Sheet 的 XLSX，或接收两段带完整表头的粘贴数据；
- 把长 ID 当字符串聚合；
- 操作已登录浏览器查询营销参谋；
- 生成可编辑中文文档；
- 区分内部事实、营销参谋证据与 AI 判断。

有 Node.js 18+ 时运行随包脚本。没有 Node 时，可用 Python、SQL、电子表格或宿主数据工具复现合同，并明确采用了等价实现，不得声称随包脚本已通过。

## 营销参谋是完整报告必经阶段

按以下顺序执行：

1. 有 `build-gcrm-hot-product-report`：复用其榜单提取、筛选与图片规则。
2. 没有该 Skill但能操作已登录浏览器：按 `gcrm-integration.md` 直接查询。
3. 浏览器未授权或页面未登录：向用户提出一个具体动作，完成后重试。
4. 页面控件不稳定：先按 `browser-runbook.md` 使用已验证的 Country tree-select、Category cascader checkbox 和浮层内自动滚动协议，再尝试浮层内视觉滚动及同登录态页面请求。不得把“可访问树没有标准下拉框”或“页面滚轮滑不动”当作失败，也不得要求用户为每个国家、类目逐组手切。所有安全路径失败时记录 `partial`。

完整报告只能使用：

- `verified`：已获取并核验营销参谋候选；
- `verified_no_candidate`：已实际完成指定国家、类目和周期的查询，但没有合格候选，并保留查询证据。

浏览器不可用、未登录、操作失败或“找不到另一个 Skill”均不等于没有候选，也不能静默跳过。若用户明确选择暂时停止，可交付醒目标注为“精品店方案部分草稿｜营销参谋待完成”的中间稿，但不得称为完整精品店方案。

## 输出适配

- 能写飞书：创建可编辑文档并回读核验。
- 不能写飞书：输出结构一致的 Markdown、HTML 或宿主原生文档，保留图片与可点击 URL。
- 能直接读 XLSX：不要要求用户转格式。
- 用户直接粘贴数据：按 `ID层级`、`名称对照` 标签识别并自行保存处理，不要求用户再制作文件。
- 宿主确实无法读取工作簿时：一次性请用户改用分段粘贴，不用技术格式术语增加理解成本。

不同 AI 可以调整卡片、表格、标题和配色实现，但必须保留 `output-contract.md` 的证据内容。不要为追求一致而逐字复刻 Sample。

## 权限边界

- 不绕过登录或权限，不索要账号密码、Cookie 或 Token。
- 不把客户数据、真实 ID、登录信息、内部截图或报告提交到公开仓库。
- 工具失败要说明真实状态，不伪造抓取、图片、链接或飞书文档。
