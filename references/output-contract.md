# 输出合同

默认交付一份可直接转发、可编辑的中文飞书文档；不能写飞书时交付 Markdown、HTML 或宿主原生文档并说明限制。只交付一个主版本。

本合同固定“信息和证据”，不固定逐字标题、段落顺序或视觉组件。使用 `assets/report-template.md` 作为设计参考，不机械填空。

## 必须出现的信息

### 首屏

- 报告标题，客户/集团名称用于标题。
- 全文数据窗口：客户货盘准确起止日、营销参谋准确起止日、生成日。
- 从数据识别到的国家和源报表金额口径。
- 一句口径说明：ID 层级数据是经营事实源；名称表只解释商品/店铺；营销参谋只验证补品。
- Top 3 精品店总表，至少包含优先级、国家与主题、承接店名和 Shop ID、方案类型（重组型/精修型）、核心货盘证据、店外候选 GMV 占比、来源店铺数和一句话理由。

证据不足三个方案时展示真实数量并说明原因，不用空行凑数。

### 每个精品店方案

内容顺序和版式可调整，但必须让读者快速找到：

1. **主题与结论：** 升级哪个现有店、面向什么用户/场景、主题边界是什么。
2. **现有好品组合：** Product ID、显示名、来源 Shop ID/店铺名、有效 GMV、可计算时的 ROAS、组合/重叠判断。
3. **迁入价值：** 候选核心 GMV、店外候选 GMV 占比和来源店铺数，并标明候选范围口径。
4. **内容打法：** 直播、短视频和达人分别怎么表达；数据证据与 AI 判断分开。
5. **营销参谋补品：** 补什么结构性缺口，附完整证据。
6. **商家评估项：** 库存、毛利、供应链、授权、履约、售后、合规和迁移成本。

不得规定最终主推款数量、SKU 数、尺寸、规格或套装数量。可以给候选和重叠判断，由商家结合经营条件决定最终组合。

若承接店内已有 GMV 占比 `>50%`、店外候选 GMV 占比 `<50%`，或已在承接店的商品原型占比 `>50%`，必须把方案标为“精修型”，说明价值来自聚焦、去杂和统一内容；不得把它包装成高迁移价值的跨店重组。精修型不机械淘汰，但默认排在真实重组型之后；例外前置必须有结构化排序理由。

完整报告同时交付并验证 `plan-evidence.json`。证据结构见 `references/plan-evidence.md`；正文中的类型词不能代替金额守恒、占比、原型数量与排序校验。

### 营销参谋补品证据

每个推荐至少绑定：

- Product ID；
- 原始商品标题和清晰中文短名；
- 营销参谋原 Shop Name；
- 国家、一级/二级类目和准确周期；
- GMV、涨幅以及 Live/Video/Card 等可用渠道区间；
- 对应商品图或真实截图；
- 可点击的营销参谋筛选页 URL；
- 含时区的采集时间；
- 为什么适合填补本主题缺口，以及试品风险。

已实际查询但无合格候选时，逐次写明筛选国家、类目、周期、含时区采集时间、实际读取行数和拒绝原因，并展示筛选 URL 与截图/DOM/导出证据引用。浏览器或授权失败不能写成“暂无候选”。

### 收尾

- 给出有先后关系的落地动作，不虚构日历承诺。
- 说明名称重复/改名不影响 ID 口径、指标缺失如何处理、未识别国家、营销参谋区间边界和迁移风险。
- 再次列出两个准确时间窗口和生成日。
- 明确候选商品 GMV 不等于客户整体大盘，也不是新店预测。

## 视觉与可读性原则

保留 Sample 的审美特征，但让不同 AI 根据宿主能力自由实现：

- 结论先行：首屏先给决策，不先铺方法。
- 层级清楚：控制在 2–3 级标题，精品店方案之间有明显留白或分隔。
- 一眼可扫：Top 3 用总表；每家店先放一句话策略，再放证据。
- 图文对应：商品图靠近对应补品表，图片、Product ID、原 Shop Name 和 URL 不分散。
- 表格克制：长解释放正文，表格保留对比较重要的字段；数字右对齐，单位和小数位一致。
- 重点色克制：只用一种主强调色加中性色，不把整页做成彩色公告。
- 重点提示适量：可用引用块、卡片或浅色底强调时间窗口、建议和风险。
- 留白优先：避免连续大段文字和超宽密表；必要时拆成小表或卡片。
- 平台适配：飞书、Aime、Mira 或其他宿主可采用各自最自然的组件，不要求逐字复刻 Sample。

不得交付占位符、假图片、无对应关系的截图或无法点击的伪链接。创建飞书文档后回读一次，检查标题、时间窗口、表格、图片和 URL。
